Continuous audit monitoring across four ERPs

Problem

The audit department needed to test transactions across four business units, each running on a different ERP. Data for testing had to come together from four very different systems.

How I approached it
  • Architected a continuous monitoring framework with automated ETL/ELT pipelines in Azure Data Factory and SQL Server.
  • Integrated Oracle, Yardi, Odoo and Keyloop data for audit analytics in Databricks and Arbutus.
  • Ran a cost analysis so the solution stays scalable and cost-effective.

Architecture

  1. SourcesOracle · Yardi · Odoo · Keyloop
  2. IngestAzure Data Factory pipelines
  3. Store & modelSQL Server / Azure SQL · Databricks
  4. TestArbutus audit analytics
  5. ReportPower BI exception dashboards

Outcome

  • 4ERP systems integrated
  • 4business units covered
  • Fullpopulation-level testing

Audit can now run exception-based and population-level tests across all four business units from a single framework.

An enterprise Databricks Lakehouse with governance built in

Problem

The firm's digital team needed an enterprise-grade platform for self-service analytics and Lakehouse modernisation, with secure, auditable access control from day one.

How I approached it
  • Owned the end-to-end architecture: data modelling, workspace design, integration patterns, reporting and CI/CD deployment.
  • Set up Unity Catalog for governance, with RBAC, cluster policies and Key Vault-backed secret scopes.
  • Built a medallion architecture using Auto Loader and Delta Live Tables, orchestrated by Azure Data Factory.
  • Extended the platform with Power BI Direct Lake, Power Apps and Power Automate, and coached engineers on reusable Lakehouse patterns.
